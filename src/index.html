Semantic caching for RAG chatbots

Answer it once. Recognize it every way it's asked.

Cachet sits in front of your retrieval pipeline. It turns every question into a vector, compares it by meaning with answers it has already given, and serves a match in milliseconds. A paraphrase still hits the cache, where an exact-match cache would miss it.

        Why semantic

        People never ask the same question the same way twice.

        A traditional cache stores answers under the exact text of the question. Change one word and it misses, so the system pays for retrieval and generation again. Cachet compares meaning instead, using an embedding model such as Qwen3-Embedding.

        How it works

        One embedding decides whether the LLM runs at all.

        Every question is embedded once. That vector is checked against past questions first. Only a miss pays for retrieval and generation, and every miss makes the next hit possible.

        1

        Embed the question

        Qwen3-Embedding turns the text into a 1024-dimension vector that encodes its meaning, in about 12 ms.

        Qwen3-Embedding-0.6B
        2

        Search the semantic cache

        An approximate nearest-neighbour index compares the vector with every question answered before, using cosine similarity.

        HNSW · cosine
        3

        Compare to the threshold

        If the closest match scores at or above τ for its cluster, the cached answer is served. Each cluster can have its own τ.

        τ = 0.88 default

        Cache hit Serve the stored answer

        The answer and its original citations come straight back. No retrieval, no LLM call, no tokens billed. The new phrasing is added to the cluster so the next variant matches even more confidently.

        Cache miss Run the RAG pipeline

        1. Retrieve the most relevant chunks from your uploaded documents.
        2. Generate a grounded answer with the LLM, citing its sources.
        3. Write the question vector, answer and source fingerprints back to the cache.
        Self-learning layer

        Runs alongside both paths. It watches hits, misses and user feedback, and adjusts thresholds, merges paraphrases and retires stale answers without anyone retuning it.

        Self-learning layer

        The cache gets sharper the more it is used.

        A fixed threshold is either too loose or too strict for some topics. Cachet learns where the line belongs for each cluster of questions, from how people actually respond to its answers.

        Adaptive thresholds

        A thumbs-down on a cached answer tightens τ for that cluster only. Consistent approval relaxes it back.

        cluster "Refund policy"
        τ 0.88 → 0.95

        Paraphrase clustering

        Every hit stores the new wording next to the original, so the cluster covers more of how people really ask.

        "PTO allowance" joined
        cluster "Vacation days" (3 phrasings)

        Freshness checks

        Each cached answer remembers which document chunks it came from. When a document changes, only the answers that depended on it are invalidated.

        Refund Policy v3 uploaded
        2 answers invalidated

        Grounding guard

        Answers with weak retrieval support are never cached, so a bad answer cannot be repeated thousands of times.
